## Project

Holeberry is a native macOS 14+ menu bar app (`LSUIElement` — no dock icon) for monitoring and controlling Pi-hole instances (v5 & v6). MIT licensed; an independent project, not affiliated with Pi-hole LLC (keep the trademark disclaimer).

Two layers:

- `Sources/Holeberry/` — the app target: menu bar UI and SwiftUI settings. UI only.
- `Packages/HoleberryCore/` — a local SwiftPM package with ALL business logic: models, Pi-hole services, browser detection, persistence.

Business logic belongs in the package; UI belongs in the app target. The app composes everything in the lazy-var dependency graph in `Sources/Holeberry/App/HoleberryApp.swift` (marked "Composition Root").

## Architecture

- **Pi-hole services** — `PiholeV5Service` (v5 web API: static token, `/admin/api.php`, HTML parsing) and `PiholeV6Service` (v6 REST `/api`, session auth via `actor AuthV6SessionProvider`, refresh is automatic). `PiholeVersionDetector` probes `/admin/api.php?version` to pick. `PiholeServiceFactory` wraps every service in `TemporaryUnblockPiholeServiceDecorator` — never bypass the decorator.
- **Menu state** — `ServerStatusPoller` (30s default) is the single source of truth; blocking toggles MUST flow through `applyBlockingChange`. Time control is abstracted by `PollScheduler` (`TaskPollScheduler` in prod, `MockPollScheduler` in tests) — no raw `Task.sleep` in production code.
- **Browser tab detection** — `BrowserTabCoordinator` state machine; Safari/Chromium via AppleScript (`-1743` error = permission denied), Firefox/Zen via `sessionstore.jsonlz4` parsing; permission checks via Carbon `AEDeterminePermissionToAutomateTarget`. Keep the strategy seams (`BrowserActiveUrlFetchingStrategyFactory`).
- **Persistence** — typed `Defaults` keys centralized in `HoleberryCore/Utils/App+Defaults.swift`; secrets via `KeychainManager` (keyed by server UUID) — never plaintext on disk.
- **Updates** — Sparkle; `Updates/appcast.xml` is committed and CI-regenerated on release.
- **Server limits** — max 2 servers (`PiholeServerManager`).

## Conventions

- Swift 6 language mode, strict concurrency. `ExistentialAny` is enabled in app and package: ALWAYS write `any Protocol` — bare existentials are compile errors.
- Protocol-driven: every dependency has a protocol seam; concrete types are named `ConcreteXxx` / `LiveXxx`. Manual constructor injection, no DI framework. Add a protocol + mock when adding a service.
- Errors: typed `PiholeError` (`LocalizedError` + `Equatable`). Network calls: `RetryPolicy.destructive` / `withRetry` (3 attempts, 1s/2s/4s backoff).
- Persistence goes through typed `Defaults` keys only; no raw `UserDefaults`/`@AppStorage` outside `App+Defaults.swift`.
- Logging: OSLog with `Logger.appSubsystem`.
- Style: 2-space indent, 120 columns, no force-unwrap in `Sources/` (relaxed in tests).

## Testing

- Swift Testing (`@Suite` / `@Test` / `#expect`) — NOT XCTest. Suites are `@MainActor`.
- Mocks live in `Tests/HoleberryCoreTests/Mocks/`, pattern: `XxxStub` (`Result`), `XxxCallCount`, `XxxLastArgs`. Add a mock for every new protocol.
- Isolated defaults via `TestDefaults.makeSuite()`; async helpers `waitUntil` / `settle` (`Tests/.../Utils/TestHelpers.swift`).
- Run: `cd Packages/HoleberryCore && swift test`. There is no app-target test bundle.
